## :dart: O guia para alavancar a sua carreira

> React é a biblioteca JavaScript mais usada do mundo para construir interfaces: você compõe a tela em componentes reutilizáveis, descreve "como a UI deve parecer" para cada estado e deixa o React cuidar de atualizar o DOM. Criada e mantida pelo Facebook/Meta, hoje é a base de frameworks como Next.js e do React Native para mobile. Este guia reúne roadmap, cursos gratuitos e pagos, documentação oficial, livros, canais, ferramentas do ecossistema (Next.js, TanStack, Zustand, shadcn/ui), comunidades e um capítulo dedicado a usar IA na prática com React — tudo verificado e organizado para quem já sabe JavaScript e quer sair do primeiro `useState` até dominar Server Components e o React Compiler.

## 🤖 IA na prática

React e assistentes de IA combinam bem porque a maior parte do código de UI é repetitivo — mas o React tem armadilhas específicas (regras dos Hooks, efeitos, re-renderizações) que a IA erra com frequência. Use isso a seu favor sem soltar a mão do volante.

**Para aprender**

- Peça para a IA **explicar por que um componente renderiza de novo** colando o código: ela ajuda a enxergar props, state e contexto que mudaram.
- Cole um `useEffect` confuso e peça: *"esse efeito é realmente necessário? Reescreva sem `useEffect` se der, seguindo a documentação oficial 'You Might Not Need an Effect'"*.
- Peça **exercícios com gabarito** sobre o tópico que está estudando (composição de componentes, `useReducer`, Context API, Suspense).
- Peça para comparar duas formas de resolver o mesmo problema (ex.: prop drilling vs. Context vs. Zustand) com prós e contras.

**Para trabalhar**

- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para: gerar componentes a partir de uma descrição, escrever testes com [React Testing Library](https://testing-library.com/docs/react-testing-library/intro/), migrar componentes de classe para hooks e criar variações de UI com [shadcn/ui](https://ui.shadcn.com/).
- [v0 by Vercel](https://v0.app/) gera componentes React/Next.js prontos (com Tailwind e shadcn/ui) a partir de um prompt ou de uma imagem de referência — ótimo para prototipar telas rápido.
- Depois de **cada** sugestão aceita, rode os testes e o linter (`eslint-plugin-react-hooks`). Se o código quebra as regras dos Hooks, a sugestão está errada, mesmo que "funcione".
- O [React Compiler](https://react.dev/learn/react-compiler) reduz um tipo de erro comum de IA (memoização manual esquecida ou errada), mas não substitui revisão humana da lógica.

**Limites e boas práticas**

- IA **inventa hooks, props e APIs** que não existem (ou existiam em versões antigas, como `componentWillMount` ou `React.createClass`). Confirme sempre na [documentação oficial](https://react.dev/reference/react).
- Ela costuma sugerir `useEffect` onde não é necessário, gerando loops de renderização e bugs sutis. Desconfie de qualquer efeito que só sincroniza estado interno.
- Cuidado com componentes de Server Components vs. Client Components: a IA mistura os dois com frequência em projetos Next.js recentes — confira sempre a diretiva `"use client"`.
- Não cole código proprietário, chaves de API ou dados de clientes em ferramentas sem a política da sua empresa.
- Entenda o que você aceita: em entrevista e em produção, o código é seu.
